# How much should you trust ForgetEval?

Ori scores 978/1000 (97.8%) on ForgetEval's template suite. Before quoting
that anywhere, here is what the benchmark is and is not, established by
reading its source and running controls through it rather than by reading its
paper.

Date: 2026-09-20. Harness: `deeplethe/lethe` @ `bench/forgeteval/`, MIT.

---

## What holds up

These are real, and they are rarer than they should be.

**The scorer computes; it does not print.** `GeneratedCase.run()` in
`generate.py` calls `recall_texts(query, k=10)` on the system itself, joins
the top ten, and tests containment. You cannot produce a number without the
system having actually emitted that text. Compare LongMemEval's
`print_retrieval_metrics.py`, which formats a metrics dict someone else
populated — "we ran the official scorer" is true there and means nothing.

**No LLM judge, no API key, no network.** Scoring is substring containment.
Generation is `random.Random(42)` over templates. The LLM hook is `llm=None`
by default and guarded at every call site. Reproducible for $0.00 by anyone,
which is not true of LoCoMo or LongMemEval's QA track.

**It is honest about capability gaps.** A system lacking `supersede`,
`release` or `purge` raises `NotImplementedError` and is scored N/A rather
than silently zero. MemPalace's published 0 is a real statement: it has no
deletion primitive at all.

## What does not

### 1. The benchmark and its top scorer are the same organisation

ForgetEval's code ships inside `deeplethe/lethe` — the repository of Lethe,
which places second at 99.3. The paper (arXiv:2606.15903) is authored by
Dongxu Yang of DeepLethe. The repo has **14 stars and 5 forks**.

### 2. Adversarial cases were admitted by the vendor's own system

253 of the 385 adversarial cases carry this annotation in `adversarial.py`:

> Generated by DeepSeek-V3 (SiliconFlow) / Structurally validated /
> **Oracle-validated (Lethe / Lethe+LLM passes the case)**

A case entered the suite only if the measurer's system solved it. The
authors' own blind 77-case external subset drops the whole field from the
63–68% band to 28–33%, which quantifies how much easier the in-house suite
is. The paper's own McNemar test across the adversarial field gives
χ²=0.125, p=0.724, and the paper says of it: *"the bench reads the
trade-off, not a winner."*

### 3. The template suite has a 35% vacuous floor — this is the important one

The oracle is `must_contain` AND `must_not_contain` over the joined top-10.
When `must_contain` is empty, the second clause is the only clause, and **a
system that returns nothing satisfies it vacuously.**

Measured on the seed-42 template suite:

| family | cases with empty `must_contain` |
|---|---|
| decay | **200 / 200 (100%)** |
| purge | **150 / 200 (75%)** |
| supersession, amnesia, drift | 0 |
| **total** | **350 / 1000 (35%)** |

Two controls, scored by the same harness
(`bench/forgeteval_null_adapters.py`):

| adapter | behaviour | template score |
|---|---|---|
| **AMNESIAC** | accepts writes, returns nothing, ever | **350 / 1000 = 35%** |
| **HOARDER** | stores everything, forgets nothing | 0 / 1000 = 0% |

AMNESIAC scores **100% on the entire decay family** and **75% on purge** by
being useless. The floor of this benchmark is 35%, not 0, and no published
table says so.

### 4. It under-penalises over-deletion, and that is not hypothetical

Nothing in the oracle punishes destroying data the caller did not name,
except `must_contain` — which is absent in 35% of cases.

Ori demonstrated the consequence on itself. An early version of
`matchForForget` had an identifier bug: the regex excluded `@` and `.`, so
emails were invisible, and `purge("alice@post.dev customer history")` matched
on the shared word "customer" and deleted **bob's** record too.

That version scored **150/200 on purge — 75%, a passing grade.** It passed
exactly the 150 vacuous cases and **0 of the 50 that could detect it.** A
system silently deleting the wrong customer's records looks fine here.

## Scoring only the cases that discriminate

Restricting to the 650 cases with a non-empty `must_contain`, where a null
system scores 0:

| | full suite | discriminative (650) |
|---|:---:|:---:|
| supersession | 100% | 200/200 = 100% |
| amnesia | 99% | 198/200 = 99% |
| drift | 99% | 198/200 = 99% |
| **purge** | **91%** | **32/50 = 64%** |
| **Ori overall** | **97.8%** | **628/650 = 96.6%** |
| AMNESIAC | 35% | **0/650 = 0%** |

Ori's headline moves little. Its **purge** number moves a lot: 91% → 64%.
Purge is Ori's genuinely weak family and the full-suite figure hides it.

The published figures for LangMem (99.5), Lethe (99.3) and Mem0 (88.8) are
full-suite and cannot be corrected without re-running those systems. The
direction is known — every one of them is quoted against a 35% floor — but
the magnitude is not, because it depends on how each behaves on the vacuous
cases.

## Adoption

One third-party run exists:
[verygoodplugins/automem-evals#31](https://github.com/verygoodplugins/automem-evals/issues/31),
opened 2026-09-18, a 10-case subset, with the full 385-case run still an
unchecked TODO. That is the entire external footprint. Trade coverage
already describes ForgetEval as "independent methodology" despite DeepLethe
authorship, so the provenance problem is propagating uncorrected.

---

## Verdict

**Sound instrument, unadopted yardstick, inflated scale.**

- The mechanism is honest: it computes, deterministically, for free, and it
  refuses to fake a capability a system lacks. That is better than most of
  this field.
- The scale is wrong: quote any template number against a **35% floor**, not
  against zero, and treat `decay` as carrying no signal.
- The adversarial ranking cannot rank its own author, and the paper agrees.
- Nobody uses it yet. "Third on ForgetEval" is third of four, in a 14-star
  repo, behind the repo's owner.

Use it as Ori does: as a **capability gate**, not a leaderboard. Its real
finding is binary and stark — most systems cannot attempt it at all, and
fifteen agent-memory vendors publish no forgetting benchmark of any kind.

Reproduce every number above:

```bash
cp bench/forgeteval_null_adapters.py <lethe>/bench/forgeteval/null_adapters.py
python -m bench.forgeteval.run --adapter amnesiac --suite template --scale 200 --seed 42
python -m bench.forgeteval.run --adapter hoarder  --suite template --scale 200 --seed 42
```
